# Kaptia 功能擴充規格與實作路線圖

本文件將目標功能拆成可逐項驗收的工程工作。**這是規格與計畫，不代表功能已經實作。** 目前公開前端是 GitHub Pages 靜態網站，既有語言引擎是本機 Qwen/ONNX；需要 OAuth、外部 API、背景執行或憑證的功能，不能只靠靜態 HTML 自動取得。

## 核心原則

- 預設繁體中文（台灣用語）；介面提供清楚的工具狀態、來源、錯誤與取消操作。
- 本機優先：聊天內容與本機文件預設留在裝置；只有使用者明確啟用某個外部工具並確認送出的資料後，才把必要資料傳給該服務。
- 工具採用「模型提出工具呼叫 → schema 驗證 → 權限/參數檢查 → 使用者確認（有副作用時）→ 執行 → 結果回傳模型 → 驗證與呈現」流程。模型文字不能直接當成可執行命令。
- API 金鑰與 OAuth refresh token 不可寫進 Git、前端原始碼、聊天紀錄或公開設定檔。
- 每項工具要有逾時、取消、速率限制、錯誤分類、最小權限、審計紀錄與測試。
- 搜尋結果、網頁、附件與第三方工具回傳內容一律視為不可信資料；不可把其中的文字當作系統指令。
- 顯示來源與擷取時間；網路工具失敗時明確說明未能查證，禁止捏造結果。
- 日曆/提醒的建立、修改、刪除，及任何對外發送、發布或連接帳戶的操作，必須先呈現摘要並取得使用者明確確認。

## 目標能力清單

| 能力 | 所需模組 | 重要限制 / 驗收條件 |
|---|---|---|
| 網路搜尋 | Search provider adapter | 有來源連結、時間、錯誤狀態；可設定允許的搜尋服務；金鑰只放在安全的服務端或使用者本機設定 |
| 擷取網頁內容 | URL fetch + HTML readability/parser | 僅允許 HTTP(S)；阻擋 localhost、私有網段、雲端 metadata、重新導向繞過及超大回應，避免 SSRF；遵守網站條款與 robots/存取限制 |
| Word/PDF/PPT/Excel/程式碼/JSONL | 檔案工作區 + 格式專用讀寫器 | 明確顯示檔案路徑、格式與大小；產出後重新讀取驗證；不把檔案建立誤報成成功下載 |
| 互動式 Artifact | 安全的預覽/發布模組 | HTML/JS 在隔離 iframe 或沙箱中預覽；預設不允許任意網路/本機存取；發布前確認公開範圍 |
| 圖片搜尋 | Image search adapter | 顯示來源與原始頁面；不將縮圖來源誤稱為擁有授權；遵守版權與服務政策 |
| 行事曆查詢/新增/編輯/刪除 | Calendar connector | OAuth 最小權限；寫入/刪除前二次確認；時區與重複事件測試 |
| Reminders 查詢/新增/編輯/刪除 | Reminders connector | 依平台 API/connector 實際支援程度開發；寫入/刪除前確認；提供回讀驗證 |
| 地圖與地點搜尋 | Places/maps adapter | 顯示地址、資料來源與更新時間；只有使用者要求或授權時才使用位置；位置權限拒絕時可手動輸入地點 |
| 體育比分與數據 | Sports data adapter | 必須用即時/近期來源；標示比賽日期、時區、資料更新時間，不使用過期快取冒充即時比分 |
| 目前位置、裝置時間 | 明確權限介面 + 本機時間 API | 位置須由作業系統權限授權；拒絕後不反覆要求；裝置時間與伺服器時間分開標示 |
| 圖表、流程圖、互動視覺化 | Visualization renderer | 圖表資料 schema 驗證；大資料集限制；提供可讀文字摘要與空資料/錯誤狀態 |
| 食譜互動卡片 | Recipe data schema + UI | 食材、份量、步驟、計時器與過敏原欄位；計量單位可轉換；不要把未驗證營養資訊當醫療建議 |
| Email/簡訊多版本草稿 | Draft composer | 可選語氣/長度/版本；預設只產生草稿，不自動發送；發送需明確確認 |
| 第三方 MCP/服務連接 | MCP client + connector registry | 顯示伺服器名稱、權限、可呼叫工具及資料傳輸範圍；每個連接器分開授權/撤銷；工具輸出不可信；高風險動作需確認 |

## 建議架構

1. **UI 層**：聊天、工具狀態、來源面板、檔案工作區、連接器管理、權限與隱私設定。
2. **本機模型層**：Qwen 負責理解意圖、產生結構化工具提案、整理結果；模型不可直接持有 OAuth token 或任意執行程式碼。
3. **Tool router**：依 JSON Schema 驗證工具名稱與參數；未知工具、超出權限、格式錯誤或超時都 fail closed。
4. **Policy/consent gate**：區分唯讀、寫入、刪除、對外傳送與公開發布；有副作用的操作先顯示精確摘要並等待確認。
5. **Connector adapters**：搜尋、網頁擷取、日曆、提醒、地點、體育、MCP 等使用獨立介面，互不直接依賴 UI。
6. **Storage**：聊天/檔案/設定預設本機；憑證存放於作業系統安全儲存區，不提交到 Git。
7. **Verification**：驗證工具回傳 schema、來源、時間戳與寫入後狀態；錯誤不可被模型改寫成成功。
8. **Static hosting boundary**：GitHub Pages 可供應前端靜態檔，但不能安全地保存第三方秘密或自行提供長時間背景服務。需要私密 API 金鑰時，應採使用者本機 connector 或經明確部署/授權的後端；若要求完全無伺服器，則必須接受某些服務無法安全或穩定整合。

## 分階段交付

### Phase 0 — 工具介面與安全底層
- 定義工具註冊表、輸入/輸出 schema、權限級別、取消/逾時與錯誤格式。
- 加入工具呼叫紀錄、來源呈現與使用者確認流程。
- 驗收：無效 schema、未知工具、拒絕權限、逾時與取消均不會執行副作用。

### Phase 1 — 本機交付與視覺化
- 建立檔案建立/讀回驗證介面；優先支援 TXT、Markdown、JSON、JSONL、程式碼與 CSV，再擴充 DOCX/PDF/PPTX/XLSX。
- 建立圖表/流程圖資料 schema 與安全預覽。
- 驗收：每種格式有 round-trip 測試；檔案失敗不顯示下載成功；不可信 HTML 在沙箱中執行。

### Phase 2 — 網路搜尋、網頁與圖片搜尋
- 使用可替換的 provider adapter；所有結果保留來源 URL、標題、時間與擷取時間。
- 網頁抓取加入 SSRF 防護、回應大小限制、內容類型驗證、重新導向檢查與逾時。
- 驗收：測試失效 URL、私有 IP、超大回應、惡意頁面指令與空結果。

### Phase 3 — 使用者授權的服務連接
- MCP 連接器先列出伺服器、工具、資料範圍與權限，再逐個授權。
- 日曆與提醒先實作唯讀，再實作新增/編輯/刪除與回讀驗證。
- Email/簡訊先只產生草稿；任何發送功能另設確認關卡。
- 驗收：撤銷授權後立即失效；刪除/發送/公開發布均需要確認；token 不出現在日誌。

### Phase 4 — 地點、體育與互動卡片
- 加入地點/地圖、體育資料、裝置時間與可選位置權限。
- 加入食譜卡片與可存取的圖表/流程圖。
- 驗收：資料更新時間、時區、拒絕權限、來源缺失與 API 中斷都有明確 UI。

### Phase 5 — 整合驗收與發布
- 端到端測試：離線、弱網路、API 配額耗盡、無權限、token 過期、惡意工具輸出、模型幻覺工具名稱。
- 建立功能矩陣，逐項標示「已實作 / 測試通過 / 未完成」，只有測試證據存在才可標示通過。
- GitHub Pages 發布前檢查 bundle 中沒有秘密；確認工作流程實際成功後才能宣稱部署完成。

## 必須先決定的產品邊界

- **完全本地端**：檔案、模型、部分視覺化與草稿可在本機；即時網路搜尋、地點/體育資料與雲端日曆連接仍需網路和對應服務。
- **不自架伺服器**：可採使用者授權的第三方 API 或本機 connector，但不能安全地把私密 API 金鑰放在 GitHub Pages 前端。
- **免費**：只能優先選擇有免費額度或本機方案；第三方免費額度、API、MCP 伺服器與平台政策可能變動，不能保證所有服務永久免費。
- **iPhone Safari**：背景執行、檔案存取、位置權限、模型記憶體與下載大小都受 iOS 限制，需在真機逐項驗收。
