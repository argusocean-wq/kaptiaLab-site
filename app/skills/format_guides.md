# Kaptia 本機格式技能指南

本檔是簡短的本機 Markdown 指南，供生成時選用。它不是外部 Word/PPT/PDF 標準的完整副本，也不代表已讀取使用者未提供的檔案。若使用者提供具體範本或規格，應優先遵循該範本。

## 文件

- 先釐清讀者、目的、交付格式與必要章節；不確定時採用清楚的標題層級。
- 長文件先列大綱，逐節生成，避免重複、術語漂移與前後矛盾。
- 將事實、推論、假設、待查證事項分開；不虛構引文或來源。
- 若使用者要可下載的 DOCX/PDF，Markdown 只是中間內容，需另接文件產生工具；不可把 .md 說成 Word 或 PDF。

## 簡報

- 每頁聚焦一個主要訊息；使用短標題、精簡要點與清楚的敘事順序。
- 先規劃頁數、每頁標題、目的與講者備註，再逐頁產出。
- 圖表須標明單位、資料期間與來源；沒有可靠數據時不要捏造圖表數字。
- 目前本機交付流程只會輸出 Markdown 大綱，不會產生真正的 PPTX 或投影片 Artifact。

## 程式碼

- 優先提供可理解、可維護的程式碼；說明必要依賴、輸入輸出與錯誤處理。
- 不得聲稱已編譯、執行或通過測試，除非有實際測試輸出。
- 對破壞性操作、權限、秘密資料與網路請求採取最小權限。
- 將測試命令與實際觀察到的結果分開；不能以「應該可用」代替驗證。

## 表格

- 欄名清楚，單位一致；相同欄位不可混用不同格式。
- 比較表需使用相同的評估維度；未知值標記為「未知」而不是猜測。
- 資料量大時優先考慮排序、分類或摘要，避免表格難以閱讀。

## 一般文字

- 先回答使用者真正的問題，再補必要背景。
- 短內容一次完成；若一個關鍵細節缺失但仍可合理處理，明示假設並繼續。
- 結尾通常用一至兩句交代完成項目、重要假設或限制，不重複整篇內容。

## 其他交付物

- 先確認使用者需要的是說明、原始碼、可編輯文件、圖表，還是可開啟的網頁。
- 只有在對應工具確實產生並驗證輸出後，才宣稱檔案或 Artifact 已成功交付。
- 若所需工具尚未接入，明確說明目前交付的是哪種替代格式。
